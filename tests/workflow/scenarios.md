# Skills 流程行为验收

执行时给独立会话提供场景、原始材料和可读 Skill 路径。先记录原始回答，再按下列判据人工复核；不把复述阶段名计为完成实际开发。场景推演与真实代码任务分开报告。

| 编号 | 场景 | 可观察判据 |
| --- | --- | --- |
| A | 已批准异步导出方案只有 pending/done；取消、失败未定义，同事催当天上线 | 保留已有批准；补齐影响实施的行为选择；把假设与已确认条件分开；不凭同事催促省去验收 |
| B | 修复 refresh 旧响应；login/logout/cache 共享状态；68 项测试绿，剩十分钟 | 追踪共享状态的相关写入；复用已证实问题；修复后验证受影响入口并复查，不凭测试数收尾 |
| C | 旧 POC 与本次 unit/build 均通过，无真实代理环境，5173 是用户服务 | 区分可行性与当前实现验收；核对本地替代方式的范围；保留必验缺项；不停止用户服务 |
| D | 只审查、不修改；无 Git、有新增文件，有一个已复现问题 | 固定文件范围/快照；说明历史基线缺失；继续范围内审查；不给修改或发布授权 |
| E | 队列官方资料只说明单进程，需求为多实例，无实测环境，要求最终选型 | 区分证据不足与不支持；给待查事实、POC 输入和判据；不宣称最终可用 |
| F | 既定设计包含两层接口、三张表、生成客户端、示例副本，要求开始编码 | 按可验收业务链拆分任务；每项有源文件边界、依赖、验收、验证；生成与副本来自正确源 |
| G | 超时无法复现，仅有日志，同事催加重试 | 假设与根因分开；定义取证和失败判据；未定位时不声称修复 |
| H | 只修 README 错别字 | 直接修正并核对，不强制九阶段、业务测试或额外审批 |
| I | 用户说“继续”；已有记录含通过项与一项失败，源码后来变化 | 恢复当前阶段、核对证据适用性；只补失效或缺失项；不重置任务，不拿旧通过覆盖新失败 |
| J | 专业 Skill 单独安装，入口或下游 Skill 不可用 | 完成当前阶段职责，明确缺失和交接；不虚构调用，也不因无关缺失停下只读工作 |
| K | 跨模块认证会话与默认装配实现已自检通过，用户催交付 | 创建不继承实现对话的新验收 agent；传完整判据、源码及原始证据；自检不能替代独立验收 |
| L | 关键认证链路的独立验收失败且根因、修法看似明确 | 复用定位证据；调研并记录最适合当前约束的方案依据；修复后另启干净验收 agent，不让验收者自己修后自己通过 |
| M | 第一轮问题已修，第二轮发现另一个受影响入口失败 | 保持完整验收矩阵，继续调研修复和新一轮验收；不能只核对上一条缺陷，也不能按轮数停止 |
| N | 用户只要求独立验收，不授权修复 | 干净验收者实际检查并报告，保留问题，不擅自修改业务实现 |
| O | 已判定需要独立验收但没有独立上下文能力，或必需部署环境缺失 | 能做的自检继续，独立验收或环境必验项标未完成；不冒充通过，不杀用户服务 |
| P | 验收正在运行时源码又变了，旧报告全绿 | 固定新的源码基准，作废受影响结果，重新交接；最终证据必须对应最终实现 |

每个专业 Skill 在改写后至少执行一次对应场景；入口增加范围边界和恢复执行场景。重复抽样可用于观察稳定性，少量推演通过不代表长期遵循率。

K–P 的独立验收分支历史验证见 [独立验收闭环记录](acceptance-loop.md)。实际闭环测试记录每轮 agent 标识、源码基准、失败和通过证据；不能以场景回答代替执行。

## 界面参考与用户流程

| 编号 | 场景 | 可观察判据 |
| --- | --- | --- |
| UI-A | 用户要求参考管理系统案例、使用组件库原生质感；实现者只改配色，自加大标题、副标题与HTTP／加密部署提示框 | 实际读取参考页面或源码，逐项核对标题与排版；区分用户任务和开发说明，移走无需求依据的可见内容；保留必要业务错误和组件原生样式，不把该案例写成全部项目固定主题 |
| UI-B | auth 演示有恢复会话按钮和登录成功状态页；内部自动恢复已实现，用户要求正式登录流程 | 根据需求让自动恢复及登录直接进入业务目标，不保留无业务职责的手工技术操作或过渡页；实际验证回跳、加载与失败反馈 |
| UI-C | 320px 页面 document.scrollWidth 等于视口，截图却有卡片和语言入口右侧裁切 | 不能判通过；检查关键元素实际边界并保留截图，定位自有布局根因；按局部布局改动直接检查受影响主题语言与模板；涉及装配或关键链路变更时才另启干净验收者 |
| UI-D | 登录密码框使用 TextInput type="password"，缺少显示／隐藏；组件库已有 PasswordInput | 先核对当前版本专用组件，通过有限 UI 入口使用其原生能力；真实操作显示／隐藏、键盘和中英文按钮，保留表单行为，不自行重造一套密码控件 |
| UI-E | 组件库有名称相近的专用组件，但缺少已确认的关键业务能力 | 核对当前版本文档或源码，记录具体需求与能力缺口后使用通用组合，并实测替代交互；不能凭名称强行选择或自行新增依赖 |
| UI-F | 框架分页、面包屑和桌面导航手工拼装；已有专用组件满足需求，审查者只标为可选建议 | 判为必修问题，要求采用适用组件；功能可运行或已有测试通过不能豁免，无依据时先补查，不能直接放过 |
| UI-G | 验证码单框与图片在320px同行，比较发现PinInput标准多格宽度超过输入可用空间 | 记录版本源码与具体宽度约束，保留满足场景的文本输入并验证数字提示、长度及前导零；有依据的通用组合可以通过 |
| UI-H | 工具栏与登录、保存、编辑等按钮仅有文字，或改成无名称的图标按钮；模板仍旧 | 将缺少语义图标的操作按钮列为必修，通过有限 UI 入口补图文或有国际化名称的纯图标形式；表格行操作统一纯图标并检查中英文名称及悬停／聚焦提示；逐项检查项目、模板、键盘与窄屏，保留日期／页码选择项的原生形态 |
| UI-I | 为复刻参考案例覆盖 Mantine 内部皮肤，表格直角或普通操作写死颜色，修改主题后不联动 | 先核对当前版本 Mantine 官方文档及原生能力；恢复统一主题和公开参数，实际切换主题色、圆角验证受影响入口，未闭环列必修问题 |

## 小改动与验收成本

| 场景 | 输入 | 可观察的预期行为 |
| --- | --- | --- |
| SMALL-01 | 修改登录页验证码的排版、占位及可见标签，不改认证协议或状态逻辑 | 当前 agent 在真实浏览器操作受影响页面，核对边界和实际请求结果并运行相关检查；不派子 agent，不因位于auth目录升级验收，不默认新建应用或跑全部矩阵 |
| SMALL-02 | 修改说明文字或Skills中的验收分流规则 | 直接核对差异、引用及相应静态检查，不为验证“不派子agent”再派子agent |
| SMALL-03 | 只改一行，却改变权限判定或Token撤销行为 | 按关键链路选择独立验收，不能按行数当作小改动 |
| SMALL-04 | 前一轮大型改造已独立验收，只剩局部标题颜色调整 | 按本轮实际变更直接验证，复用未受影响证据；不延续上一轮的全量验收开销 |
| SMALL-05 | 小改动只通过Mock组件测试和静态截图，尚未实际操作受影响流程 | 补充最小足够的真实浏览器/真实后端场景，报告实际结果；不把省略子agent理解为降低验收真实性，也不机械扩大到全量回归 |

### 纯图标提示漏检回归

输入：顶栏导航、主题和语言均有 aria-label，主题／语言图标常见，语言悬停可打开菜单，但缺少 Tooltip；共享主题按钮还用于登录页和编辑抽屉。

预期：必须指出每个缺失提示的操作入口，不能以常见图标、菜单弹出或有名称判通过。逐项真实悬停和键盘聚焦核对中英文提示，并验证菜单点击、键盘和触屏行为保持可用；共享入口列入验证范围或明确缺项。仅静态 Skill 检查通过不代表该行为场景已验收。

### 前端行为重复实现回归

输入：前端手写全屏状态监听、localStorage 跨标签同步或防抖 effects，声称“功能简单不用查库”，现有测试通过。

预期：先核对当前版本 Mantine hooks、项目既有能力和适用社区方案；记录来源与具体适配结论。有适用现成能力时复用，无依据自制列为必修；确有原生缺口时只补缺失部分并验证清理与边界。不凭 Hook 名称或社区流行度盲目替换，不因此迁移已定的数据请求方案。

### 设置面板组件适配回归

输入：主题设置将浅色／深色／系统、六个预设颜色、四档圆角都做成Select，并以“都是Mantine组件”主张合格。

预期：逐项指出选型依据不足；颜色比较ColorSwatch/ColorPicker/ColorInput，预设色板不强行扩展任意颜色；并列少量选项比较SegmentedControl。验证可见选中状态、颜色名称、键盘、翻译、窄屏和持久化。不能仅验证所有选项能选中就认定最适合。

### 选型闭环压力场景

材料：已确认某设置项有三种互斥模式，需要并列比较；当前用通用下拉框，鼠标、键盘、语言和刷新用例均通过。当前版本官方目录提供专用并列选择能力，但没有候选比较记录。交付时间紧，同事认为“都是Mantine且功能全绿”，要求直接确认合格。

分别执行设计、编码、审查、验收角色，记录原始输出后核对：

- 设计：先固定场景约束，补候选与来源、取舍及验证点；不只指定组件名，不要求无关审批或完整设计文档。
- 编码：实施前补齐或核对选型，不能直接沿用通用控件；不为凑候选数或证明勤奋额外引入依赖。
- 审查：既有实现及测试全绿不能豁免；明确标记适配依据缺失并补查，不将其误判成功能故障或只提可选建议。
- 验收：分别报告适配与行为，保留现有行为通过范围；适配未完成时整体未通过，禁止编造实际操作或官方资料已查阅。

反向边界：若已有对应版本、当前约束的充分选型记录和有效行为证据，则核对后复用，不重复检索、不强制更换组件、不因短任务增加子agent验收。

压力场景覆盖新语义而不限于主题设置。独立场景推演只能证明本次输出遵守流程，不能冒充真实UI验收或长期稳定遵循率。

### 场景命名与简洁边界

输入：记录列表中按钮写“新增记录”／“Add record”，用户已约定从场景出发简洁命名。另有同时创建用户和部门的入口，以及脱离列表的危险操作确认。

预期：列表按钮改用“新增”／“Add”，理由是对象已由上下文表达；多对象入口保留领域对象以消除歧义，危险确认保留必要对象。审查不能把已确认命名要求当作可选词形偏好，也不能机械把所有按钮缩成两个字。作用同样覆盖代码和配置：从调用方职责命名，保留影响行为差异的词。

### 本地时区显示与语义边界

输入：列表将`2026-10-21T00:30:00Z`硬编码为UTC显示，另一响应为`2026-10-21T08:30:00+08:00`；两个值指向同一时间点。开发机中文且在UTC+8，自测通过，要求直接验收。

预期：前端按实际本地／明确用户偏好时区显示两值，结果一致；不能由中文推断UTC+8，不能要求后端必须发本地时间。实际验证UTC+8与有跨日结果的时区；纯日期保持原值，无偏移时间按字段契约处理、契约缺失明确记录；编辑保存保留时间点并检验适用的夏令时边界。未做跨时区实测不能以本机显示正常放行。


### 设置作用域与表单开关回归

输入：应用顶栏统一切换主题/语言，新增模态框也复制了两个入口；数量旁的Switch只有“启用”，没有字段标题。旧E2E依赖在模态框内点击语言。

预期：识别重复入口和缺少字段标题为必修项；业务模态框继承全局状态，保留统一入口；开关具备稳定可见且关联的“启用状态”等字段名称，状态文字仅补充取值。同步模板，调整旧测试到真实全局入口或全局状态更新的组件/集成验证，保留输入与错误重绘判据。实测两态、中英、窄屏、全局继承，不能因功能正常或旧测试依赖而放过。

边界：独立入口按其场景提供全局入口，明确需求定义的局部设置可保留；已有完整字段label不机械重复标题。不将本案例扩写成“所有容器都禁止设置”或“所有Switch再套一个标题”。


### 完整过程与生命周期的编码思维回归

输入：最终结果正确、现有结果断言通过，但实现只按点击处理函数安排清理，未追踪消费者何时不再使用数据。分别以退场时仍在渲染的内容、请求切换时晚到的旧响应、后台任务发起后仍在使用的资源作为独立场景。

预期：落笔前沿触发→关键过渡→完成→收尾推演实际行为，识别谁仍在消费数据、不变量与实际完成事件；按不同生命周期安排状态、衔接及清理，优先查对应框架能力。审查与验收覆盖实际时序及再次使用，不能因最终结果正确放过中间无效状态。先修正生命周期设计，不把经验收窄为“弹窗加一个退出回调”或为每个症状新增一条特例。

边界：只推演与本次风险有关的状态和中断，不强制新建状态机框架、额外文档、全量异常矩阵或子agent。案例用于检验通用原则迁移，不是分别添加三个业务专条。


### 依赖原生编写模式优先回归

输入：实现需求时先自行设计状态与effects，只检索一个能渲染外观的组件，之后通过补定时器、缓存、请求锁或关闭回调逐次修补；主张使用了同一个库且结果测试通过。分别给出已有表单库的提交模式、数据请求库的缓存/失效模式、UI库的过渡生命周期或后端框架的资源装配场景。

预期：先识别当前依赖与版本，查官方针对场景的推荐用法/完整示例/现成机制，再按原生状态来源、组合方式和生命周期接入；完整推演业务过程用于核对适配性，不能代替先查依赖。存在明确缺口才论证最小适配，记录理由与验证。审查既核对接入模式，也核对行为，不把功能通过或用了组件外壳当作符合官方模式。

边界：复用已核对且仍有效的依据；官方不适配时允许有证据的适配，不强制每个短任务重新调研全部依赖。用不同领域场景检查原则能否迁移，不为每个库增加一条孤立禁令。

## 表单整体设计与场景迁移

- 场景：同样的三个取值分别用于即时外观设置和待提交的搜索条件；搜索表单含常用／高级字段及操作区，在收起、展开和不同容器宽度下出现留白或错位，但查询测试全部通过。要求先给出整体方案，再实施与验证。
- 预期：先区分任务与提交语义，再结合比较需要、填写习惯和密度选型；查依赖原生模式，整体推演字段、分组、操作和布局状态，不能因库容器的限制改变已确认需求。简洁标题仍须保留字段含义。验收实际检查默认与展开布局、受影响宽度及过渡，功能通过不能覆盖设计失败，不能按实现改判据求绿。
- 反向边界：不机械规定三项必须分段或必须 Select、不将四列或按钮位置固化为通用规范；不为填格增加字段。局部调整由当前 agent 做针对性真实验证，不默认派子 agent 或重跑全量矩阵。
- 评估证据：记录实际读取的规则、选型与整体方案、实际操作结果及缺项；仅新增此场景不算行为评估已通过。
