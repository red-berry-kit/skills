# 错误反馈与诊断回归场景

用于编码、审查和验收 Skill 的后续行为回归。以下是输入及判据；新增规范的静态检查不等于这些场景已经在真实应用执行。

| 场景 | 输入 | 必须观察到的行为 |
| --- | --- | --- |
| ERR-01 | 初始化提交收到密码字段 422，随后状态 refetch，输入与字段错误被卸载 | 判定为缺陷；区分首次加载与后台刷新，保留输入和错误；实际验证复查完成后仍可见、修改密码后纠错并重新提交成功，后端不记录该正常拒绝的业务错误日志 |
| ERR-02 | 服务端返回未映射字段位置，客户端 catch 后仅写 console | 将错误回退到表单或操作级提示，展示可公开原因与恢复方式；只写控制台或后端日志不能通过 |
| ERR-03 | 后端故障统一变成“请求失败”，响应只含 500，日志也只有“调用失败” | 前端获得安全说明、恢复建议和关联编号；后端记录操作、阶段、调用目标、错误原因链、耗时及关联标识，不暴露秘密 |
| ERR-04 | 请求总耗时 12 秒，含排队、数据库、外部调用和三次重试，只有最终 access log | 指出阶段耗时与重试失败日志缺失；优先使用原生 hook 和现有设施，逐阶段记录结果、耗时及父子关联，重试逐次记录并有最终总结果 |
| ERR-05 | 保存失败后自动查询成功，页面误提示“保存成功”；或刷新失败后旧数据看起来仍是最新 | 分开写入结果与查询状态；保存失败持续可见，后台刷新失败明确标注且保留可用旧数据，用户可纠正或重试 |
| ERR-06 | 密码错误、输入不合法或可预期冲突都打印 WARN，理由是“所有错误都应记录” | 判定为分类错误；前端保留可纠正反馈，后端正常返回业务错误，不额外记录正常拒绝；不以 HTTP 状态码或返回 error 决定程序故障 |
| ERR-07 | 异步任务已受理返回 202，之后外部服务失败，前端一直转圈 | 任务状态返回可理解的失败与恢复入口，关联提交请求和后台执行日志；受理成功不能代替任务完成，失败有终态与耗时 |
| ERR-08 | 每层重复记录同一异常，SQL 参数和令牌被直接打印 | 在掌握上下文的边界完整记一次，下层保留原因链；复用统一脱敏和关联设施，保留诊断信息并移除敏感原值 |
| ERR-09 | 性能排查只有请求总耗时，没有阶段、等待及外部调用耗时 | 按项目日志级别取得实际阶段记录，定位瓶颈；优先使用原生 hook 和现有设施，不机械在每行代码打日志 |
| ERR-10 | 用户主动取消被当作异常打印堆栈；后台真实依赖超时却被一并忽略 | 区分预期取消与非预期超时；前者正常收尾，后者记录技术原因和耗时并给用户恢复反馈 |
