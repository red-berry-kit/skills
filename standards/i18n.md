# 国际化（i18n）

新增或调整用户界面、用户可见的 API 响应、校验提示或语言格式时适用。先核对项目已约定的支持语言、默认语言、语言选择与持久化、缺失翻译回退及前后端翻译分工；已有约定直接复用。尚未确定的语言范围与技术选型记为决策缺口，不擅自固定中英双语或新增翻译框架。

## 职责与装配

应用统一管理语言策略。模块随包提供自己命名空间内的消息资源，通过公开装配契约接入；CLI 创建应用和添加模块后按约定自动装配，消费应用只填写必要配置。模块不读取宿主私有翻译文件，多个模块的同名消息不互相覆盖。

翻译键表达稳定语义，动态值通过完整消息的参数传入，沿用已选库的插值和复数能力。用户输入与业务数据保留原值；协议字段、资源标识、路由与机器可识别的错误身份保持稳定。日志和内部异常面向运维，不因响应语言切换改变错误分类，也不直接充当用户提示。

明确用户可见消息由前端还是后端翻译，或按消息类别划分；同一条消息只由约定的一层翻译。对外返回文字的后端接口也在范围内，不能仅完成页面翻译就认定国际化完成。前端细则见[前端国际化](frontend.md#国际化i18n)。

## 时间显示

时间点由前端按[本地时区](frontend.md#本地时区)转换显示，语言选择不决定时区；保留纯日期及接口原始时间语义。跨语言验收与跨时区验收分别记录，不能用其中一项代替另一项。

## 验收

按项目约定的语言范围实测新增及受影响的文案、可访问名称、格式、缺失翻译回退与长文案布局。支持语言切换时检查菜单、已显示错误、页面标题和控件随之更新，会话与表单保留；单语言范围核对页面、控件及响应语言一致。

后端覆盖业务错误、自动请求校验、未识别内部错误及本次受影响的其他用户可见消息；对比不同语言时，HTTP 状态、错误身份、字段位置和业务结果保持一致。服务端支持语言协商时，验证默认、支持、不支持或无效语言以及并发不同语言请求相互隔离；前端翻译模式验证结构化错误及未知错误的安全回退。

可复用模块在干净应用通过真实 CLI 添加后验证资源装配及前后端消息链路。只找到翻译函数、资源文件或确认视觉正常，均不能代替实际国际化验收。记录实际语言、入口与结果，未实现或未执行的项目保留缺项。
