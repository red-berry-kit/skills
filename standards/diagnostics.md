# 错误反馈与诊断

前端错误反馈的目的是让用户知道哪里有问题、如何调整或恢复操作。后端日志的目的是让开发者定位程序故障、分析耗时并优化性能。按这两个目的分别决定展示内容和记录内容。

## 失败分类

先判断失败是否属于程序预期，再决定是否记录诊断错误；HTTP 状态码、返回 error 或进入 catch 都不能单独作为判断依据。

| 情况 | 前端处理 | 后端日志 |
| --- | --- | --- |
| 正常操作错误，如输入不合法、密码错误、权限不足、重复提交或可预期版本冲突 | 展示可公开原因及对应调整方式 | 正常返回业务错误，不记录该拒绝的业务错误日志 |
| 程序缺陷、不变量被破坏、异常依赖响应、连接故障或非预期超时 | 展示安全说明与恢复方式，必要时提供关联编号 | 记录技术原因、上下文、关联标识及发生阶段 |
| 用户主动取消等预期控制流 | 展示取消后的状态，保留允许继续的内容 | 不记程序错误；按性能记录需要保留状态和耗时 |
| 正常执行、等待及调用耗时 | 按产品流程呈现进度与结果 | 记录性能耗时，供定位瓶颈和调优 |

同样的 404 或冲突可能是正常业务结果，也可能来自错误路由、异常依赖或程序缺陷，应根据实际原因分类。正常操作错误不因降为 INFO 或 DEBUG 就变成需要记录的诊断事件；已有访问及性能日志可保留请求状态和耗时，不重复打印正常拒绝的详情，也不将其计为程序故障。

## 用户反馈

所有用户操作失败都有对应的可见反馈，包括客户端校验、服务端业务拒绝、网络、超时及异步任务失败。反馈说明失败的操作、可公开的原因和下一步：修改哪些输入、重新登录、重新加载、重试或携带关联编号联系维护者。不能只在控制台或后端写日志，或将失败显示为成功、无限等待。

字段错误显示在对应字段，其余错误显示在表单、页面或任务状态；服务端未知字段位置也要有操作级反馈。可纠正的原因保留其具体语义；内部异常显示安全说明与恢复指引，SQL、堆栈和技术细节留在诊断日志。响应遵守接口声明的错误契约，语言处理按项目国际化契约。

错误收到后立即显示，持续到相关输入纠正、新结果替代或流程结束。后台复查不能卸载表单、清空输入或抹掉未解决的错误；后台刷新失败可保留旧数据并标明刷新未成功。具体表单生命周期见[表单状态与提交](frontend.md#表单状态与提交)。异步任务受理成功不等于任务执行成功，失败须有可读取的终态与恢复入口。

## 程序故障日志

记录程序故障及非预期依赖故障的错误类别、原因链、发生阶段和必要上下文；未预期异常在捕获边界保留定位所需堆栈。包含时间、级别、模块、操作、请求／任务关联标识，按场景补充资源标识、调用目标、尝试次数及超时配置。日志应能回答“哪次操作、哪一步、为什么异常”。

在掌握完整上下文的边界记录一次故障，下层传播原因链，避免逐层重复打印。异常重试逐次保留技术失败和耗时，最终记录恢复或失败结果；重试成功不抹去用于诊断的异常记录。WARN／ERROR 根据实际影响和项目约定选择，不将正常业务拒绝升级为警告。

关联标识贯穿请求与异步任务，用户需要联系维护者时可通过已有响应头或公开错误契约获得编号。客户端网络失败可能尚未到达后端，不能虚构后端已接收的请求或日志。响应与日志均过滤密码、令牌、Cookie、密钥及不必要的个人数据；SQL 参数、请求体和第三方响应按字段脱敏。

## 性能耗时日志

沿实际执行链覆盖请求／命令／任务总耗时、各处理阶段、排队与锁等待、数据库与事务、缓存、文件、外部 HTTP／RPC／模型调用，以及配置加载、迁移、启动、后台执行和关闭的耗时点。记录阶段结果与明确单位的耗时，如 `duration_ms`；失败和超时也有对应耗时。长阶段记录开始与完成，便于定位未完成的等待。

耗时包含等待，嵌套与并发阶段保留父子关系，避免重复相加。复用项目日志级别区分汇总与细节，调试时能取得完整阶段信息；只记录整项总耗时不能定位内部瓶颈。性能日志不附带正常业务拒绝的错误详情，也不为每行代码或简单函数调用机械打印日志。

优先复用已有请求日志、数据库／客户端原生 hook、生命周期事件和日志／追踪设施，按[依赖原生模式优先](conventions.md#依赖原生模式优先)接入。只有缺失的业务阶段才补最小埋点，避免复制计时包装或另建同类框架；指标和 trace 不替代明确要求的耗时日志。

## 验收

针对受影响链路分别验证以下结果，记录实际界面与日志证据：

1. **正常操作错误**：用户能看到原因并完成纠正；后台复查后错误与可继续使用的输入仍在；后端没有该拒绝的业务错误日志。
2. **程序或依赖故障**：用户得到安全的恢复反馈；开发者能通过关联标识查到技术原因及发生阶段，日志无重复和敏感值。
3. **性能诊断**：从实际日志能分辨总耗时、阶段及外部调用耗时，定位等待或瓶颈；超时和失败路径也有耗时。

按变化选择实际场景；纯文档变更核对规范与引用，不能将静态检查表述为应用链路已经通过。编码和审查使用同一判据，避免只检查“返回了错误”或“打印了日志”。
