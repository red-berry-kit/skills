# 设计与架构

设计模块、应用或共享机制时，在本页确定所有权、依赖方向与装配边界。命名和实现方法读取[开发约定](conventions.md)，具体工具及版本读取[技术选型](stack.md)；文档归属按 [Skills 说明](../README.md#内容归属)维护。

## 模块边界

- **模块身份**：用户业务与基础能力均使用独立模块，分别声明身份、版本、依赖和公开入口；共用项目结构，前端、后端及迁移按需加入，不预先固定业务功能。
- **公开协作**：跨模块只通过所属模块声明的公开入口协作。按真实文件归属检查依赖，覆盖别名、软链接与再导出；动态导入使用固定字面量。
- **基础维护**：基础模块与公共工具集中维护，使用方按版本升级；自定义行为放业务模块或独立实现，不在外部源码目录长期修改。
- **源码归属**：自有模块放项目内模块目录，外部源码放 Git 忽略的 `.redberry/modules/`；提交 YAML 清单和锁文件，依赖声明与锁定结果须可重现。
- **替代实现**：通过 `replaces` 声明目标模块 ID 与大版本。消费方继续依赖目标约定；同一目标只允许一个实现，选择后全项目生效。替代维护者负责契约兼容，框架执行正常编译与边界检查，不另建健全性评估机制。

## 装配与工具职责

| 责任方 | 负责的内容 | 边界 |
| --- | --- | --- |
| Red Berry CLI | 模板创建、源码与版本管理、工作区、模块解析及装配输入 | 将输入填入模板并执行必要依赖接入；维护依赖不得删除自有业务源码 |
| 依赖注入 | 后端构造器、对象、资源与生命周期组合 | 与 CLI 共用模块图，不让业务分别维护安装图与装配图 |
| 前端装配 | 静态可见入口、完整路由树 | 保留入口与路由的类型关联 |
| 项目任务脚本 | 统一生成、检查、测试、开发及构建入口 | 只做转发，由 CLI 编排并调用编译器、检查器和测试工具 |
| Skill | 决定何时调用工具、如何判断结果及继续任务 | 不重复实现命令能力；编程约束通过类型、规则与检查反馈 |
| 业务 Agent 工具 | 业务模块需要的运行时操作 | 按模块单独设计，不预设通用工具集合或统一注册层 |

- **约定发现**：通过固定路径发现模块入口和资源，不在各模块重复声明。
- **生成来源**：生成产物的问题改在源码、生成输入或官方配置，再从项目入口重跑；不手工修改生成结果，不通过覆盖旧产物掩盖不一致。
- **正式交付**：通过项目已有任务入口生成、检查、测试与构建；局部 POC 不替代正式交付。工具、命令及运行方式见[技术选型](stack.md)。

## 独立应用边界

同一宿主交付多个应用时：

- **资源所有权**：各应用独立拥有入口、路由、静态资源与处理链，共享进程或二进制不改变所有权。构建产物和嵌入资源按应用或资源类型分目录，应用名、资源索引及目录名一致。
- **访问隔离**：应用不得读取或暴露其他应用资源，不得依赖其他应用挂载路径；共享能力通过公开接口接入。
- **声明装配**：统一声明应用名称、产物及页面／资源挂载规则，由通用机制校验和分发。新增应用只提供声明与产物，不应修改宿主代码、复制应用专属中间件或为应用名新增分支。
- **边界处理**：明确处理路由冲突、API 边界、资源缺失及路径穿越；声明不足时扩展通用契约，不增加应用特例。
- **验收判据**：覆盖开发、单文件与分离部署的入口、资源、深层路由、缺失资源及隔离；增加第三个应用验证扩展能力。改变一个应用的挂载路径或资源不应改变其他应用。

## 扩展槽位与链式透传

模块通过 Fx 的 `group:"..."` 值组和 `Provide*` 注册参与装配，按最弱机制优先选择扩展方式：

| 机制 | 允许的操作 | 必须保留的边界 |
| --- | --- | --- |
| 只读监听：事件、group 消费 | 观察 | 不改写、不截断 |
| `Provide*` 值组注册 | 追加一项贡献 | 不改变其他项；重复名称或标识按装配约定拒绝，不静默覆盖 |
| 链式 `Operation(ctx, next)` | 改写上下文或拦截 | 不拥有决策的中间件调用 `next(updated)`；改写时保留已有字段，不整体丢弃 |
| 唯一槽位构造器 | 独占一个能力 | 多实现显式失败，不按加载顺序选择 |

提供者在公开契约中分别声明容量和顺序：

- **容量**：可叠加槽位聚合多个贡献，全部生效、不覆盖、不合并；唯一槽位恰好一个实现，多于一个时在装配期显式报错，不回退或覆盖。
- **无序（默认）**：贡献相互独立，不保证消费次序，不假定其他贡献的副作用已发生；先后关系用依赖或同一贡献内部串行表达。
- **显式排序**：仅用于确有叠放语义的槽位，按公开契约声明的排序字段和同序规则处理；HTTP 中间件按 `Order`、同序按名称。排序字段由提供者在源码声明，不经配置或运行期指定。
- **核对注册**：新增或调整槽位后同步容量与顺序契约，用只读 `redberry inspect --group <槽位名>` 核对安装图中的模块及源码引用。标签出现处只证明注册事实，槽位语义以公开契约为准。

## 前端状态与公开入口

- **界面入口**：业务通过正式 `@red-berry-kit/ui` 组合控件与页面容器；工作台使用 `@red-berry-kit/web`。主题与组件入口由 ui 模块集中维护，接法读取实际安装版本的 `README.LLMS.md`。
- **列表状态**：列表条件保存在 Router URL；分页以服务端响应为准，表格字段与页码转换集中在边界。
- **编辑状态**：表单使用统一状态来源，业务校验交已选表单校验库；保存放在 `onSubmit`，服务端字段错误回填表单库提供的提交错误槽。
- **表格状态**：表格使用其统一状态来源，不与表单编辑状态混用。
- **专题处理**：日期、时区及语言按[国际化](i18n.md)处理；失败展示与恢复按[错误反馈与诊断](diagnostics.md)处理。选用的前端库和样式方案见[技术选型](stack.md#前端)。

## 接口与校验职责

| 边界 | 权威输入与责任 |
| --- | --- |
| API 定义 | 从 Go 类型及接口注册生成 OpenAPI，再生成客户端类型与调用入口；生成工具见[技术选型](stack.md#api-客户端) |
| 服务端输入 | 校验外部请求是否合法 |
| 表单输入 | 校验编辑状态中的业务约束 |
| 客户端调用 | 使用生成类型与入口，不增加重复的请求／响应 Schema 校验；HTTP 错误按接口契约处理 |
| 开发期检查 | 检查代码、类型、规范及模块边界，不能替代服务端输入或表单业务校验 |

## 配置校验分层

按检查是否需要资源划分校验职责：

| 阶段 | 检查对象 | 执行入口 |
| --- | --- | --- |
| 结构 | 字段类型、必填、默认值、枚举和范围 | 统一配置 Schema |
| 静态语义 | 不依赖资源的字段语义与配置关系 | 模块纯语义校验，由统一配置加载触发 |
| 运行时 | 资源可用性、初始化结果及实际能力依赖 | 资源启动阶段 |

- **复用判定**：纯配置语义使用运行模块提供的纯校验入口，由自检与启动共用；不得仅写在构造器里。
- **自检边界**：静态检查不启动进程、不监听端口、不连数据库、不执行迁移；需要资源的确认留启动阶段或显式 dry-run。
- **跨模块关系**：两端配置可得时，纯配置关系通过独立配置检查验证；依赖实际资源的能力在启动阶段验证。
- **错误归属**：按[错误聚合格式](diagnostics.md#错误反馈与聚合)返回完整字段路径；本节只规定何时检查，不另定义错误文本格式。
