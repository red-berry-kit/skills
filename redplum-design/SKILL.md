# 红梅设计

以实际需求和现有架构为起点，形成可实施、可验证的方案。遵循目标项目规范；红梅源码仓库的流程见[设计流程](../../docs/design.md#设计流程)，涉及模块协作时阅读[模块与依赖](../../docs/modules.md)。

## 工作步骤

1. 确认输入。阅读需求、验收条件、现有实现与调研结论，明确变更范围和已有约束。需要查清的事实交由调研，尚未确认的需求明确列出。
2. 划分职责与协作。说明各模块负责什么、通过哪些公开接口协作以及依赖方向。接口需表达调用方必须知道的输入输出、不变量及错误行为；新增接口或抽象围绕实际变化点建立。
3. 设计关键行为。按本次变更涉及的内容，说明数据流、资源生命周期、事务提交与回滚、并发条件及外部副作用的执行时机，覆盖成功与失败路径。已有能力直接复用，并验证新增组合。
4. 选择实现方式。以简单直接的方案为基线，有实质取舍时比较替代方案。采用设计模式或增加抽象时，说明解决的具体问题、收益及维护成本。
5. 交付方案。明确接口和受影响文件或模块、实施顺序、验收场景及适用限制。已有初步方案且需要实战定案时，给出 POC 的候选、输入与验收条件，再依据结果完善设计。

## 方案产出

- **目标与范围**：需求、约束、验收条件及变更边界。
- **职责与行为**：模块及接口、依赖方向、关键调用流程和失败处理。
- **选择与验证**：实现方式及取舍、实施安排、验证条件和待确认事项。

每项验收条件应能对应到设计中的行为及验证安排。设计说明不代表代码或实验已经执行。

设计深度随任务规模调整。沿用现有设计的小修改直接说明局部改法及验证范围，无需完整方案或额外文档。需要保存时，已定规则写入对应专题，调研比较与实验材料放项目已有过程资料区。
