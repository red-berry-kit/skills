# 红梅排障

从问题证据定位根因，再做针对性修复。遵循目标项目约定；红梅源码仓库的流程见[排障流程](references/design.md#排障流程)。

## 工作步骤

1. 明确现象。记录预期与实际行为、触发步骤、环境、输入及影响范围，区分用户反馈、已有执行证据和待验证解释。
2. 建立失败判据。优先使用可重复的最小复现或测试，确认其失败确实对应原问题，保留修复前结果。无法复现且证据不足时，明确缺少的条件，继续采集相关日志、请求响应及执行上下文。
3. 验证根因。结合实际代码和数据流提出可验证假设，每次针对一个因素检查，记录支持或排除它的证据。需要核实库行为时按项目约定查对应版本资料。
4. 针对性修复。在明确的问题位置修复原因，遵守编码约定，保留无关行为。修复范围由证据决定，不因暂时缓解或相关现象就认定根因成立。
5. 回归与交付。用原失败判据复验，再覆盖受影响的边界和项目必需检查。确认原问题消失且相关行为保持正确，记录实际结果及未验证范围。

## 排障记录

说明现象、复现与取证方式、根因及依据、修改位置、修复前后结果和剩余限制。按实际情况区分已确认原因、待验证假设和无法复现；信息不足的故障继续收集证据，不描述为已修复。

测试围绕问题的可观察行为建立，保留失败与成功记录。最小复现通过只证明其覆盖范围，真实接口、浏览器或部署环境的验证单独说明。执行过程中的临时服务和资源按项目约定清理，结果留在已有过程资料区。
