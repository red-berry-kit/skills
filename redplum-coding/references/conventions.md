# 开发约定

本页是日常开发的规则索引。字段、参数和目录的完整定义以所链接专题为准。

## 设计与命名

- 约定优于配置：通过固定路径发现入口和资源，不在每个模块重复声明。
- 命名兼顾语义与链路一致性，在此前提下使用清晰短名，不为对齐单个库破坏整体约定。
- 优先复用依赖原生能力、标准格式与社区约定，缺口才补小范围适配。
- 用户业务与基础能力都是独立模块，前端、后端和迁移按需加入。

定位与职责见[设计与架构](design.md)。

## 规则执行方式

命名与代码风格优先遵循 Go、TypeScript 及已选框架的社区惯例；需要统一跨模块行为时补充项目规则。规则正文在对应专题维护，Skill 引用规范。

| 规则范围 | 执行方式 |
| --- | --- |
| 格式、导入顺序、基础语法与类型 | 格式化工具、Lint、编译与独立类型检查 |
| 模块依赖方向、公开入口、生成代码边界与 UI 使用范围 | 静态检查，统一接入 `redplum check` |
| 文件名、标识符及 API 字段命名 | 遵循既有规范，可自动检查的部分接入工具 |
| 职责划分、抽象与设计模式 | 编码 Skill 指导设计与自查，结合代码审查 |
| 调研、POC 与测试覆盖 | 编码 Skill 要求提供来源、验收条件及实际验证结果 |

编码 Skill 的职责与流程见[设计与架构](design.md#编码-skill)。

## 文件与公开入口

- Go 模块文件在各自模块根；项目启动入口是 `cmd/<项目命令名>/main.go`，装配位于同目录 `bootstrap.go`。
- 模块后端入口为 `backend/module.go`，导出 Fx `Module`；前端公开入口为 `frontend/index.ts`，使用具名导出。
- 跨模块只通过公开入口引用，包括类型；模块内部可引用自身实现。私有目录的 `index.ts` 不自动成为公开入口。
- 自有模块放项目内的模块目录，ID 后缀即该目录；外部依赖及生成产物在 `.redplum/`，整体 Git 忽略且可恢复，不保存业务自定义。
- `migrations/` 放模块根，与 `backend/`、`frontend/` 平级，不把各模块 SQL 复制到项目根。

具体文件见[目录结构](structure.md)，依赖、替代与生命周期见[模块与依赖](modules.md)。

## 依赖与生成

- `redplum.yaml` 管模块依赖，`redplum.lock` 锁定实际选择；Go 和前端包仍通过各自依赖文件管理。
- `deps` 支持精确版本和 `^`；`replaces` 只声明目标大版本，同一目标全项目使用一个实现。
- CLI 维护源码、工作区与生成装配，用户不手工维护 Go 本地映射；生成文件不手改。
- 依赖维护操作不能删除自有模块源码；检查不通过覆盖生成文件掩盖不一致。

完整规则见[模块与依赖](modules.md)、[CLI 约定](cli.md)。

## 后端业务

- 业务依赖通过构造参数传入，容器操作集中在装配层；资源获取与释放交给 Fx 生命周期。
- 运行配置只通过统一入口加载，显式零值参与覆盖，合并与校验通过后才注入；修改后重启生效。
- Go 类型与注册生成 OpenAPI；业务返回普通 Go 错误，由接口层映射 Huma 原生错误响应。
- 列表使用 `page`、`size`，响应返回实际分页值；常规编辑使用完整 `PUT`，区分未传、null 与零值。
- 大整数资源 ID 使用字符串；普通业务时间点统一 UTC、毫秒精度，纯日期保持字符串。
- 一次项目迁移的所有待执行步骤与版本记录共用一个事务；此范围不延伸到普通业务事务。

细则见[配置](config.md)、[API 契约](api.md)、[数据迁移](migrations.md)。

## 前端业务

- 业务 UI 使用 TSX，通过有限 UI 入口组合页面，沿用统一主题；内部样式由基础 UI 按需使用 CSS Modules。
- 模块引用按真实文件归属检查，覆盖别名、软链接及再导出；动态导入使用固定字面量。
- 通过生成的 Fetch / Query 入口访问 `/api`；强校验约束代码和边界，不增加重复的客户端请求、响应 Schema 校验。
- Router URL 保存列表条件；分页以对应服务端响应为准，Table 的字段与页码转换集中在边界。
- TanStack Form 管编辑状态，Zod 管表单业务校验；保存位于 `onSubmit`，字段错误用原生提交错误槽回填。
- 日期与时间控件沿用 Mantine dates；纯日期不做时区转换，时间编辑明确时区并保留未修改的原始值。

主题、控件、状态与错误处理见[前端开发](frontend.md)。

## 运行、检查与发布

- 项目统一入口为根 `package.json` 的 `dev / gen / check / test / build / build:split` 脚本；命令采用子命令在前、参数在后的写法。
- `pnpm dev` 默认 dev 环境；后端手动重启，前端使用 Vite HMR。构建不携带运行配置，发布模式由 `pnpm build` 与 `pnpm build:split` 选择。
- 统一检查覆盖业务、模块和生成代码，业务不自行关闭既定规则；Vite 构建与测试不代替独立 tsc。
- 测试默认零重试，统一入口校验必需层、退出码与结构化报告；空集合和异常报告不能视为成功。
- CI 先恢复依赖和必要产物，再执行 `check` → `test` → `build`。检查不自动修复。

命令与进程行为见[CLI 与开发流程](cli.md)，工具版本和测试层次见[技术选型](stack.md)。
