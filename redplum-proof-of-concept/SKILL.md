# 红梅 POC

对已有初步方案开展实战验证，依据验收结果定案。遵循目标项目约定；红梅源码仓库的完整流程见[POC 流程](../../docs/design.md#poc-流程)。

## 工作步骤

1. 固定输入。明确候选方案、目标环境与版本、真实使用场景和必需验收项。尚未查清的事实先调研；尚无初步方案时先完成设计或选型。
2. 搭建真实接入。按验收范围在项目已有实验区搭建最小可复现场景，固定依赖及必要锁文件，覆盖要求中的模块、持久化或前后端调用链路。孤立示例只作为其实际范围内的证据。
3. 逐项执行。运行对应的生成、编译、类型与静态检查、场景测试；逐条记录通过、失败或未执行。核对实际步骤是否覆盖全部必验项，再判断整体结果。
4. 分析并调整。保留失败证据，分析配置、版本、接入方式或候选是否需要调整。修正后复验受影响链路，补齐缺项；保持既定检查标准，生成代码的问题修在生成输入、官方配置或方案中。
5. 给出决策。全部必需验收通过后，给出对应范围内的可行结论及适用限制；否则说明阻断、缺项和下一轮安排。决定调整目标时明确新的方案与验收基线，保留原结果的适用范围。

## 验证记录

交付候选及环境、复现输入与命令、逐项验收状态、失败原因、限制和决策建议。原始日志、必要代码及锁文件留在项目过程资料区。执行时管理好启动的服务与临时资源，在结束或失败时完成清理。

主方案正文仅同步最终确认的有效规则；候选进度、失败过程及未验项保存在实验记录，实现进度独立维护。未定案时保留原有效方案，不将本轮收尾安排写成正式选型。

POC 通过只证明记录范围内的可行性，正式模板、CLI 或业务功能的实现与交付另行验证。只评阅已有材料时标明本次没有重新执行。
