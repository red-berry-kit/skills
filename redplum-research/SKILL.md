# 红梅调研

为当前决策提供有来源的结论。遵循目标项目的调研约定；红梅源码仓库的流程见[调研流程](../../docs/design.md#调研流程)。

## 工作步骤

1. 明确问题与约束。读取相关实现、已定方案、依赖版本和已有实验，确定本次需要回答的问题与验收条件。已有结论按版本、环境及验证范围判断是否可复用。
2. 查证事实。按项目约定使用可用的文档与检索工具，优先官方文档、对应版本源码、发布记录，再结合社区实践。每项影响决策的事实附具体来源，注明其适用版本及条件；资料冲突时核对来源和范围，缺失项明确保留。
3. 形成判断。结合现有技术栈、维护成本、静态检查及 Agent 开发边界评估方案。选型时分别核实维护活动与实际采用证据，依据当前维护仓库、版本和使用场景判断。
4. 交付结论。当证据足以回答当前问题时结束调研，使用下述结构交付。尚未查清的事实继续查证，材料或访问受限时说明缺口；已有初步方案且需要实战定案时，给出 POC 输入与验收条件。

## 结论结构

- **结论与状态**：回答当前问题，说明是事实结论、初步推荐还是已定方案。
- **依据与适用条件**：关键事实及来源、目标版本和环境；将项目判断与来源事实分开。
- **限制与下一步**：未查明的事实、尚未实测的行为，以及相应的查证或验证安排。

简单事实查询可直接回答并附来源。需要复用的调研报告放项目已有过程资料区；主文档仅同步最终确认的有效规则。只有实际执行过的实验才能作为验证证据，旧结果的适用范围以原环境和用例为准。
