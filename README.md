# Red Berry Skills

从 [using-redberry](using-redberry/SKILL.md) 选择阶段、恢复任务与组织交付；按需读取专业 Skill。验收方式、独立验收交接与证据规则见 [redberry-verification](redberry-verification/SKILL.md)。

## 在项目中使用

将 Skill 目录安装到客户端支持的位置，可安装整套或单独使用。安装、更新后核对实际路径与发现结果，必要时让客户端重新扫描。由开发者安装和更新，Red Berry CLI 不管理 Skills；仅引用名称不算已安装或执行。

规范通过 `standards/` 的远程地址按需读取，离线使用前预先镜像该目录。

项目 `AGENTS.md` 引用以下入口，并保留项目特有规则：

> Red Berry 的需求、调研、设计、实现、排障、验收与审查使用已安装的 `using-redberry`；按入口读取所需专业 Skill，维护当前阶段、产出、证据与下一步。复用已有授权及有效结论。

编写模块 `README.LLMS.md` 时使用 [redberry-writing-readme-llms](redberry-writing-readme-llms/SKILL.md)：写使用约定，公共入口附短注与代码链接，详细接法留在代码注释中。

## 内容归属

| 材料 | 唯一负责的内容 |
| --- | --- |
| `using-redberry` | 阶段选择、任务恢复、修复循环和最终交付 |
| 各专业 Skill | 本阶段的输入、动作、完成条件和交接；只引用相关技术规范 |
| `standards/` | 下表划分的跨模块技术规则，不复制阶段流程或模块 API |
| 模块 `README.md` | 模块介绍 |
| 模块 `README.LLMS.md` | 使用约定、公共入口短注与链接；具体签名、参数、示例放代码注释 |
| 项目或模块 `AGENTS.md` | 源码维护与验证要求，保留项目特有约束和 Skill 入口 |
| `tests/workflow/` | 行为场景和历史验证证据，不列为项目开发必读资料，不改写历史事实 |

模块 API、CLI 参数、生成目录和运行库细节由实现方随代码维护；读取实际安装版本，本仓库不另设转述或逐项跳转文件。

## 规范分工

每条技术规则只在所属文件完整定义；跨主题任务读取多个文件，不在各文件重复展开同一规则。

| 文件 | 回答的问题 | 内容边界 |
| --- | --- | --- |
| [开发约定](standards/conventions.md) | 实现时如何判断？ | 命名、依赖现有能力复用、行为过程与生命周期 |
| [设计与架构](standards/design.md) | 谁拥有、谁装配、谁校验？ | 模块／应用边界、扩展槽位、前端状态、接口与配置分层 |
| [技术选型](standards/stack.md) | 用什么工具、版本和命令？ | 技术栈、版本、运行入口、静态检查及测试执行要求 |
| [错误反馈与诊断](standards/diagnostics.md) | 失败如何返回、展示和排查？ | 错误分类与聚合、用户反馈、故障及耗时日志 |
| [国际化](standards/i18n.md) | 语言和时间如何表达？ | 翻译分工、语言状态、消息资源、日期时间语义及验收 |

跨主题要求按各自责任分别定义，通过条件引用关联，不在某一专题包办其他专题的规则。

## 维护

- **Skill 组织**：源码在独立仓库根的 `<skill-name>/SKILL.md`，名称与目录一致；专业 Skill 使用 `redberry-` 前缀。新增 Skill 须有独立触发场景；补充资料可用参考文件，无需规范的 Skill 保持自包含。
- **加载边界**：本目录不实现自动加载，按客户端机制读取。缺少某项 Skill 时说明缺失并继续有依据的工作，不伪称使用；Red Berry CLI 不覆盖 Skills，`.redberry/` 不保存 Skills。
- **语言与引用**：英文 `description` 写触发条件，正文与说明用中文；规范按场景引用远程地址，不复制副本。
- **规则表达**：每条聚焦一个可判断的要求，明确对象、条件、动作或边界；删除背景、原理、效果宣称和重复释义。相关条件与例外就近组织，以职责和行为差异区分条目，不只拆段或减字。
- **抽象层级**：通用规则按职责、契约、条件与判据编写，不以特定业务、界面或工具的案例作为规则主体。专题约定保留必要的技术事实与边界，不把通用化写成无法判断的泛泛要求。
- **规则迁移**：按上表归并重叠内容，同步有效引用，核对条件、授权、失败处理和交付要求均有去向。
- **规则验证**：实现变化时同步规范；可自动检查的要求接入 `redberry check` 或 `task check`，其余明确由评审核对。规范变更至少抽查一条断言与实际行为一致；流程变更核对阶段选择、产出与交接，不只匹配标题。

规范变更后执行：

```bash
python3 scripts/check-skills.py
```

流程变更先核对实际失败或对照行为，再按风险选择静态检查、场景推演或独立执行；局部调整不默认展开多 agent 对照实验。

静态检查覆盖元数据、Skill 名称引用、包内链接与锚点，以及本仓库规范远程地址对应的文件与锚点。分别报告静态检查、推演、真实执行与未验证项，不以静态通过推断行为效果。
