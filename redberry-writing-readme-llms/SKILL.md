# 模块 README.LLMS.md 编写

在 `README.LLMS.md` 编写本模块的使用约定，附相关公共入口短注与代码链接，按使用能力组织。

## 内容归属

先按责任确定内容去向，每条规则只在所属位置完整定义：

| 内容 | 所属位置 |
| --- | --- |
| 本模块的使用前提、调用方责任、行为边界与公共入口 | 本模块 `README.LLMS.md` |
| 模块介绍 | 本模块 `README.md` |
| 签名、参数、字段、配置项、命令项、默认值、详细接法与示例 | 实际声明及其代码注释 |
| 源码维护与验证要求 | 适用的 `AGENTS.md` |
| 应用入口、路由、运行环境、偏好作用域与部署 | 应用资料；不在模块说明中代写应用方案 |
| 通用流程与跨模块规范 | 原有权威来源；按适用条件引用 |
| 技术选型与版本清单 | 项目独立选型资料与依赖声明；不写入使用规范 |

涉及外部协作时，只写使用本模块所需的调用方条件；其他模块自身的职责与接法留在其使用说明。删除实现原理、内部机制、未提供能力清单及源码目录介绍；其中影响使用的真实限制改写为适用条件或行为边界。

## 内容写法

- **使用视角**：以调用方使用本模块的公开能力为对象，写它必须提供、执行或保持什么。模块已经完成的转换、状态管理和生命周期处理，不再写成调用方动作。
- **可判定要求**：按需要写明适用条件、责任主体、动作及结果或边界；读者应能判断何时适用、做什么、何时满足。将泛泛的质量要求改成具体检查对象，不强制每条凑齐固定句式。
- **条目区分**：每条只承载一个可独立判断的要求；无关责任分开，同义要求合并，同一要求的条件与例外就近写。相邻条目用对象或动作区分，不用换词重复同一要求。
- **正向表达**：优先写允许且应采用的做法；安全、授权、数据完整性及必要旁路限制保留明确禁令，有可行替代时同时说明替代做法。
- **抽象层级**：规则围绕职责与公共契约，不以特定业务案例、实现步骤或底层依赖的接法作为主体；保留影响正确使用的具体语义与失败边界，不把规则泛化成口号。
- **按需引用**：条件分支才需要的详细资料，以适用条件和直达链接引导读取；共同必需的规则留在当前能力节。已有权威定义直接引用，不复制同一规则或用连续跳转藏住必要前提。
- **术语与精简**：沿用本模块及公开契约的实际名称。删除背景、设计理由、效果宣称与重复释义；能直接从声明读取的细节留在声明处，正文保留使用者据此必须作出的选择或动作。

## 统一格式

一级标题固定为 `# <模块名> 使用规范`。正文按能力使用二级标题，每节依次包含：

- `## <使用能力>`：标题直接表达使用场景，不按包或文件分组。
- `约定：`：独立一行，空一行后用 `- ` 列出具体规则。
- `公共入口：`：独立一行，空一行后用 `- ` 列出入口，每条为名称链接、中文冒号和用途短注。

标题、标记和列表之间留一个空行。统一使用这两个标记；场景限定写入具体规则。没有独立规则或入口的内容并入相关能力，不添加空章节；有独立规则但无需显式入口的节省略 `公共入口：`。

## 编写

1. **核对来源。** 阅读现有使用规范、公开声明、代码注释及必要实现和测试，为待写规则确认来源。用户已确认约定与实现有缺口时，明确受限条件并保留待办；仅承诺已保证的行为，证据不足的判断保留为待核实，不为配合文案修改运行行为。
2. **按能力归类。** 按“内容归属”确定每条要求的去向，再按“内容写法”和“统一格式”编写。读者应能从能力节判断使用前提、自己的责任及允许的边界，方法清单不能替代使用规则。
3. **就近列公共入口。** 只列调用方需要显式使用或声明的公开入口，内部协议钩子留在代码。每条写名称、用途短注及实际声明文件的相对链接；名称有歧义时加包名。同一能力且声明同处的入口可合并，不同声明位置分别链接；再导出索引不能代替实际声明。文档源码链接与合法导入入口分别核对，不让读者据此导入私有文件。
4. **补齐详细接法。** 沿入口链接检查注释能否指导接入；细节缺失时，仅在已授权源码范围补注释，保留实现行为。无源码修改授权时报告缺项，不以扩写正文、仅跳转介绍或虚构接法代替。

## 验证

- **规则核对**：逐条检查内容归属、适用条件、调用方动作与判据；对照公开接口及必要实现，确认没有把内部处理写成外部责任，也没有把实现细节提升为使用要求。相邻条目能独立判断，同义要求只有一处完整定义。
- **入口核对**：逐个确认入口确为公开且需要使用，链接直达对应声明，短注与实际用途一致，声明注释提供必要接法；参数、回调和状态语义均与该入口一致，不套用其底层依赖的接口。
- **完整性核对**：对照修改前内容，确认使用前提、条件与例外、授权、安全、失败处理及交付约束均有去向。只在有依据时修改保证范围；实现缺口与未核实项单独记录，不以删除约束或改写历史消除缺项。
- **格式与交付核对**：检查能力标题、标记及列表顺序，文件统一命名 `README.LLMS.md` 并随模块交付。改名或迁移时同步有效引用、模板与交付测试，保留历史事实。

完成条件：每条规则有依据且可判断，每个公共入口能直达实际声明与必要接法，职责归属无越界、重复或遗漏；交付实际检查结果及仍有的缺项。静态检查只证明其覆盖的结构与引用条件，不作为文档执行效果或运行行为通过的证据。
