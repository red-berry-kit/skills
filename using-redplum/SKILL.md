# 使用红梅开发

组织任务并按需使用专业 Skill，复用项目规范、现有实现与工具。流程随任务规模裁剪，简单修改无需展开全部阶段。

## 理解任务

1. 阅读目标项目的 `AGENTS.md`（如有）和相关实现，明确目标、变更边界及验收条件。已有结论仍适用时直接复用。
2. 以目标项目文档为准，按变更范围阅读专题。红梅源码仓库的规范入口是[开发约定](../../docs/conventions.md)；涉及架构和流程时阅读[设计与架构](../../docs/design.md)。不要将红梅源码仓库的目录位置当作所有业务项目的安装约定。
3. 仅询问会影响结果且无法自行查明的问题。任务已明确时继续推进，不为例行步骤反复请求确认。

## 选择能力

| 任务情况 | 使用的 Skill |
| --- | --- |
| 编写或修改业务代码 | `redplum-coding` |
| 新需求、核实技术事实、寻找现成方案 | `redplum-research` |
| 调整模块职责、接口、依赖方向、抽象或设计模式 | `redplum-design` |
| 已有初步设计或选型结果，需要实战验证后定案 | `redplum-proof-of-concept` |
| 报错、行为异常或性能问题 | `redplum-debugging` |
| 用户要求审查，或重要变更完成后 | `redplum-code-review` |

按实际依赖顺序组合能力，不逐项机械执行。需要实战定案的任务采用“调研 → 初步设计或选型 → POC 实战验证 → 根据结果定案 → 正式实施”；尚未查清的事实继续调研。

通过客户端可用机制使用对应 Skill；不支持 Skill 间调用时，读取已安装的对应 `SKILL.md`。若所需 Skill 尚未提供，明确缺失项，依据可用的项目规范推进已明确的工作，不声称已调用或执行该 Skill；缺失内容影响决策时先解决该缺口。

纯说明、简单查询和文档纠错直接处理，无需展开完整开发流程。创建模块、开发接口及开发页面沿用专项参考流程（如有），不要自行假定另有同名 Skill。

## 实施与验证

- 按可验证的小步实施。遇到需要改变方案的情况，回到对应设计或选型步骤。
- 格式、类型和可静态检查的边界交给项目工具，执行方式遵循目标项目的 CLI 与 Task 约定。先确认命令及所需能力可用，不将设计中的命令视为已实现工具。
- 根据需求、变更风险与影响范围运行检查及必要测试。涉及调用链路时验证真实接入，POC 或局部测试通过不代表正式功能已交付。
- 重构组合设计与编码，并验证既有行为；依赖升级组合调研、必要的 POC、编码及验证。

## 交付

核对验收条件，按变更范围进行审查并同步文档。主文档只保留最终有效规则，调研比较、实验代码及执行证据保存在项目已有过程资料区；不要求每一步新增文件。

报告实际变更、实际执行的检查测试及结果，明确未完成与未验证范围。未执行的验证不得描述为通过。
