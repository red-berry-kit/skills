# 红莓实施计划

输入为验收条件、已定方案、现有实现和验证条件。将范围拆为可独立判断结果的工作单元。已有计划有效时直接复用；流程由 `using-redberry` 组织。

## 执行

1. 核对关键行为已明确、关键可行性已有依据。业务语义缺口交 `redberry-requirements`，设计缺口交 `redberry-design`；仅规划不依赖未决项的部分。
2. 沿完整业务链拆任务，列出源码、调用方、生成输入及接入位置。每项记录：**目标行为／依赖／改动范围／对应验收条件／验证方式**。基础设施任务注明为哪条业务链提供能力，避免只列“后端、前端、测试”而无法验收。
3. 根据依赖排序，提前核实测试入口、所需服务和环境。与状态或资源共享有关的变更，列出受影响操作与要保持的不变量；为这些操作安排验证，不能只覆盖报错的那个入口。
4. 新增或改变可复用模块默认装配与核心能力时，安排干净消费应用的真实 CLI 安装与核心操作验收，将生成器／模板的缺口纳入对应任务，不能只验证已经接线的示例。将必要的生成、示例同步、迁移或配置调整、与变更风险匹配的验收及代码审查纳入安排；按 `redberry-verification` 选择方式，需要独立验收时再准备交接材料与环境。命令以目标项目实际定义为准；环境缺口注明影响与可行替代范围，不用替代环境抹去必验项。

## 出口与交接

每条验收条件均有实施任务和验证去向，每个任务的前置依赖可判断，未决事项没有被写成已完成。将计划更新到同一任务记录，交 `redberry-coding` 逐项执行；已获授权且条件满足时直接继续。

局部修复可压缩为一行：“修复某调用的过期结果提交；覆盖共享写入入口；以乱序复现与相关回归验收。”无需固定任务数量或新增计划文档。只要求计划时，交付计划及缺项，不开始编码。
