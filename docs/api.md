# API 契约

Go 类型与接口注册是 API 的统一来源，Huma 生成 OpenAPI，Orval 生成前端类型、Fetch 调用和 Query 接入。生成文件不手工修改。

强校验约束代码、类型、规范与模块边界；客户端不重复执行请求或响应 Schema 校验。服务端输入校验、表单业务校验与 HTTP 错误处理分别承担各自职责。

## HTTP 响应与错误

成功响应直接返回接口声明的业务结构，使用 Huma 原生响应输出方式；有响应体默认 `200`，无响应体默认 `204`，其他成功状态在接口注册时按语义声明。

失败响应采用 Huma 原生 `ErrorModel` 和 `application/problem+json`，使用实际 HTTP 错误状态码。`status`、`title`、`detail` 表达错误概要；`errors` 中的 `location` 与 `message` 表达具体字段位置和原因，其他字段遵循 Huma 原生模型。

接口通过 Huma 原生错误 API 声明状态与错误详情。成功与错误响应一并由 Huma 描述到 OpenAPI，前端基于生成类型和 HTTP 状态处理。

业务层返回普通 Go 错误，保持与 HTTP 无关；接口层通过 `errors.Is`、`errors.As` 识别错误语义，并使用 Huma 原生错误 API 映射状态码，例如资源不存在返回 `404`、状态冲突返回 `409`、无操作权限返回 `403`。未识别的内部错误按 `500` 处理。

所有失败路径均提供供前端显示的错误语义，覆盖自动校验、业务拒绝、依赖故障及异步任务失败。按[错误反馈与诊断](diagnostics.md)区分用户可纠正原因与内部故障，分别处理前端恢复指引和后端诊断；正常业务拒绝返回对应错误，不记录业务错误日志。

## 错误响应国际化

新增或调整返回给用户的错误、校验消息及其他自然语言响应时，遵循[国际化契约](i18n.md)，明确消息由后端翻译还是由前端基于结构化语义翻译。成功响应中面向用户的提示也遵循相同分工，业务数据不自动翻译。

业务层保留与语言无关的错误语义，由接口边界按项目契约映射用户消息。调用方通过 HTTP 状态及项目约定的稳定错误身份判断业务分支，不能比较已翻译的 title、detail 或 message 文本。错误身份沿用既有类型或标识契约；需要增加机器可读字段时先设计兼容方式并同步 OpenAPI，继续使用原生问题响应模型，不另包一层响应结构。

采用服务端翻译时，明确请求语言来源、支持列表、默认与回退优先级，以及响应语言的标识方式；语言状态限定在单次请求，不能以全局可变 locale 处理并发请求。接入共享缓存时区分语言变体。采用前端翻译时，返回稳定的错误身份、字段位置及安全的插值参数，未知错误使用约定的通用提示回退。

覆盖业务错误、框架自动请求校验和统一内部错误处理链路。按契约处理 ErrorModel 的 title、detail 及 errors[].message，保持 status、errors[].location 等结构化语义；不能只翻译手写错误而遗漏自动校验。未知内部错误对用户返回安全的通用消息，原始异常、SQL、凭据与堆栈留在受控诊断中，不直接拼入响应或翻译参数。认证等敏感错误保持既定信息披露边界，不因语言变化暴露额外原因。

接口测试除逐语言消息与回退外，核对状态码、错误身份、字段位置及业务结果不受翻译影响；服务端语言协商另验证并发隔离。验收场景见[国际化验收](i18n.md#验收)。

## 列表查询

统一使用页码分页。请求与响应中的 `page`、`size` 同名，响应表示本次实际返回的数据页。

| 请求参数 | 含义 | 默认与约束 |
| --- | --- | --- |
| `page` | 页码，从 1 开始 | 默认 `1`，最小 `1` |
| `size` | 每页数量 | 默认 `20`，范围 `1–100` |
| `sort` | 有序的排序字段列表 | 接口声明枚举，逗号分隔，`-` 前缀为降序 |
| 具名筛选参数 | 接口支持的筛选条件 | 接口声明类型、枚举和范围 |
| `q` | 接口需要文本搜索时使用 | 接口说明搜索字段 |

默认值与范围声明在 Go 参数类型中，由 Huma 校验并同步到 OpenAPI；非法参数返回 `422`。

| 响应字段 | 含义 |
| --- | --- |
| `items` | 当前页数据，空结果为 `[]` |
| `total` | 相同筛选条件下的总记录数 |
| `page` | 服务端实际采用的页码 |
| `size` | 服务端实际采用的每页数量 |

页码超过最后一页时，服务端调整为第一页，返回该页数据及实际分页值。空结果返回 `page: 1`、`items: []`，`total` 按相同筛选条件计算。

分页参数与响应使用 Go 类型声明，由 Huma 生成 OpenAPI，再由 Orval 生成前端参数、响应类型和调用。

排序使用逗号分隔的 `sort`，如 `sort=-created_at,id`。后端通过 Huma 的数组参数与字段枚举声明排序能力，Orval 生成排序字段类型并序列化为 CSV。字段顺序决定优先级，`-` 表示降序；重复或相互冲突的字段返回 `422`。后端白名单映射数据库列，并以唯一键补足稳定排序。

筛选采用接口具名参数，在 Go 类型中声明类型、枚举和范围。需要文本搜索的接口使用 `q`，并说明搜索字段。分页、排序和筛选共用相同条件计算 `items` 与 `total`。

页码是对外接口约定，底层查询仍可能使用数据库 OFFSET，不因此保证大页码查询性能，也不承诺计数与数据读取之间或跨请求的快照一致性。

响应示例：

```json
{"items": [], "total": 0, "page": 1, "size": 20}
```

前端的 URL、缓存键、Table 状态与响应回写规则见[列表状态](frontend.md#列表状态)。

## 更新接口

常规编辑采用完整 `PUT`，请求类型声明本接口的全部可编辑字段；ID、审计时间等只读字段由响应类型承载，不要求提交。完整更新中的字段声明为必填，允许清空的字段同时声明可空；缺字段返回 `422`，不将缺省解释为保持原值。

可空字段使用 Go 指针且不添加 `omitempty`，由 Huma 同时生成 required 与 nullable，Orval 生成必填的 `T | null`。`null` 表示清空；`false`、`0`、空字符串是显式值，是否允许由字段约束决定。数据库更新明确写入可编辑列，不过滤零值或空值。

前端提交完整可编辑状态，响应与后续查询回填保留 `null`、零值和空字符串的区别，见[表单状态与提交](frontend.md#表单状态与提交)。

部分更新或特定业务操作由模块按需显式声明，模板不自动生成 PATCH 路由，也不要求所有模块引入通用三态包装。部分更新若允许清空字段，须明确区分未传与 `null`。涉及并发防覆盖的资源，由模块定义版本或条件写策略，完整 PUT 本身不隐含此保证。

## 业务资源标识

账户等持久身份实体默认采用 UUIDv7，以规范 UUID 字符串对外传输，数据库主键显式声明非空与唯一。复用成熟生成库并显式处理生成失败；已有外部标识契约或纯演示固定数据按其约定保留。UUIDv7 的时间有序结构不能替代数据库唯一约束，主键冲突不得覆盖既有记录。验证码、恢复码、会话秘密继续采用密码学随机生成，不能用可排序 ID 替代秘密凭据。

资源需要乐观锁时，使用从 1 开始的正 int64 版本，通过数据库 `version = version + 1 WHERE id = ? AND version = ?` 原子比较并递增，依据受影响行数拒绝旧写入。认证安全代际与资料版本分开，安全变化与业务数据在同一条件更新／事务中递增安全代际；资料修改保留会话。版本耗尽时拒绝更新，不能回绕或复用。API 版本使用规范十进制字符串，持久模型与接口类型显式转换，Schema 与实际 JSON 保持 string，前端原样回传；避免仅用 `json:",string"` 改写 JSON 而保留整数 Schema。

接口中的数值 ID 仅在能保证 JavaScript 安全整数范围（绝对值不超过 `9007199254740991`）时使用 JSON number；需要覆盖大整数或不透明标识时使用 JSON string。字段类型按接口固定，不根据单条数据的大小切换。

字符串 ID 在 Go 接口类型中使用 `string`，Huma 据此生成字符串 Schema，Orval 保留字符串类型。数值型 ID 使用字符串传输时，数据库模型可继续使用 `int64`，接口边界通过标准库转换并校验范围，非法输入返回 `422`。不单独用 `json:",string"` 改写序列化而保留整数 Schema。

字符串 ID 在前端请求参数、Query key、Router 状态和 Table 行标识中保留原值，不进行数值转换。URL 状态通过 Router 的类型化导航或链接生成，遵循其默认查询参数序列化规则。

## 时间与日期

普通业务时间点使用 Go `time.Time`，接口表示为带时区的 RFC 3339 字符串，OpenAPI 类型为 `string/date-time`。领域写入边界使用标准库统一为 UTC、毫秒精度，创建、更新与后台写入遵循相同规则；响应返回归一化后的实际值。不固定字符串的小数位数。

Orval 保持默认字符串类型，不开启自动 Date 类型或响应转换。前端在显示与控件边界按需转换，网络数据和缓存保留字符串；时间点按[用户本地时区](frontend.md#本地时区)展示，正确解析响应中的UTC或其它有效偏移；不要求服务端返回用户本地时间。无时区的 `datetime-local` 值不能直接作为时间点提交，也不能无条件追加 `Z`。

纯日期使用 `YYYY-MM-DD` 字符串，Go 接口字段声明 `format:"date"`，由 Huma 校验真实日历日期，前端保持字符串。SQLite 可存为文本；生日、账期日期等纯日期不经 JavaScript Date 或时区转换。

需要亚毫秒精度的业务字段单独声明精度、存储与传输契约，不沿用普通业务时间默认规则。
